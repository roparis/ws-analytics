## ⚠️ This app is in production — a premise several plans got wrong

Discovered 2026-08-16 while opening PRs: `https://ws-analytics.vercel.app` is
this repository's homepage and has served **12 production deployments** since
2026-08-11, running this exact build — both API routes included.

The original audit and several plans reasoned as though the hosting question
from `docs/yahoo-pricing-poc.md` §6 were open. It is resolved in practice, and
that changes real conclusions:

- **015** excluded rate limiting and origin checks as near-worthless "for a
  local-first single-user run". Wrong premise. §6 item 2 — *"Deployed publicly
  they are an open Yahoo proxy — and the history route is the expensive one"* —
  describes production. The history route turns **one inbound request into up to
  101 upstream Yahoo requests** (one per symbol at `MAX_SYMBOLS`, plus FX),
  unauthenticated and unthrottled. 015 now includes an origin check and a lower
  history-route ceiling; a shared-store rate limiter is flagged as a maintainer
  decision, not an executor's.
- **007** preferred client-side caching partly because hosting was "undecided".
  That reason is gone; the privacy argument for client-side remains and is now
  the actual one.
- **014** was told not to resolve the hosting question. It must now describe
  both cases: self-hosted, the server is your own machine; on the hosted
  instance, a user's tickers pass through someone else's deployment.
- **Account IDs in URL paths** (below) now reach Vercel's access logs, and a
  **CSP** (deferred) is more relevant than when it was assessed.

Honest bound on the risk: nothing user-derived is stored server-side, so this is
cost and IP-reputation exposure — your Vercel invocations, and Yahoo potentially
refusing the deployment — not a data breach.

### ⚠️ `pnpm typecheck` fails on a clean checkout until plan 001 lands

**This affects every plan in this directory**, because they all carry a
`pnpm typecheck` done criterion and executors work in fresh worktrees.

`tsconfig.json` includes `next-env.d.ts` and `.next/types/**/*.ts`. Both are
gitignored (`.gitignore:17` and `:45`) and generated by `next dev` / `next build`
/ `next typegen`, so on a clean checkout neither exists and `tsc` cannot find

src/app/layout.tsx(25,50): error TS2304: Cannot find name 'LayoutProps'.

**If you are executing a plan before 001 has landed**: run
`pnpm exec next typegen` once after installing dependencies, then proceed
normally. This is environment setup, not a deviation from your plan, and not a

## Findings considered and rejected

Recorded so they are not re-audited next time.

**Rejected as incorrect** (subagent findings that did not survive verification):

- *A staged CSV export in `public/`.* There is no `public/` directory in this
  repository at all. The finding was fabricated.
- *The `coverage` object identity defeats the analytics page's memos*
  (`analytics-overview.tsx:144`). It does not. `coverage` resolves to
  `dataset.dateRange`, a stable reference, whenever `dataset` exists; the fresh
  `{ start: "", end: "" }` literal only materialises when `dataset` is null, and

  repeated.
- *The "Year to date" filter preset resolves to 31 December of the prior year.*
  It does not. `resolveDateFrom` returns early for `ytd` via pure string
  arithmetic (`dashboard-filters.tsx:32`), never reaching the `Date` path. The
  underlying bug in that function is real but affects only the 30d/3m/6m/12m
  presets, and is fixed by plan 009.
- *Passing a no-op logger to `yahoo-finance2` would stop ticker symbols reaching
  server logs.* It would not. The `console.error(url)` in the library's fetch
  path is not routed through the configurable logger, so a custom logger cannot
  suppress it. Recorded in plan 015 as explicitly out of scope for that reason.

**Rejected as not worth doing:**

- *Decomposing `src/lib/google-sheet.ts` (1366 lines), `src/lib/positions.ts`
  (1008), or `src/lib/metrics.ts`'s derivation core.* Long, but coherent and
  unusually well-commented. Splitting the eight sheet builders would trade a
  readable module for a directory of files sharing an implicit contract about
  anchor rows.
- *Adding jsdom + Testing Library for component tests.* `vitest.config.mts`
  records a deliberate choice ("Every module under test is pure functions over
  plain objects — no DOM"), the suite runs in ~260ms because of it, and the
  untested code that actually endangers money is `merge.ts` and
  `parseActivities`, not JSX. Revisit only if a component bug costs something.
- *An XLSX / Google Sheets **import** to pair with the export.* Looks like a
  missing pair and is not. The round trip that matters — prices back in —
  already exists (`parsePriceCsv`). The workbook's other tabs are derived views
  the app can always recompute, so reimporting them would create a second source
  of truth for numbers the app already owns.
- *A generic multi-broker CSV importer.* The value of this codebase is
  `docs/wealthsimple-csv-format.md` — 530 lines of Wealthsimple-specific rules,
  most of which exist because the intuitive reading is wrong. A generic importer

  standard would be real direction; "more formats" would not.
- *The `nanoid` advisory (GHSA-2v37-7h3g-55p8, high).* Reached only via
  `@tailwindcss/postcss > postcss` at build time. The vulnerability needs an

## Deferred, with the evidence — do not re-derive

Two findings from the original audit were reassessed against the code and
deliberately left unplanned. The evidence below is what changed the assessment.

**Sharing the `buildPositions` walk.** Audited as a MED-impact, S–M-effort win;
it is smaller and more dangerous than that.

- *The trap*: `src/components/charts/capital-chart.tsx:127` calls
  `buildPositions(activities)` **without** `{ sources }`, while
  `src/components/dashboard.tsx:46` calls it **with** `{ sources }` — on the
  **same array identity**, on the same route. `options.sources` is read once
  (`positions.ts:748`) and only affects `historyConfidence`, `historyReasons`
  and `issues`; every numeric field is identical either way. So a
  `WeakMap<Activity[], PositionsReport>` keyed on the array alone would, depending
  on render order, hand the sources-aware callers
  (`investment-overview.tsx:33`, `account-breakdown.tsx:51`) a report with the
  merge-conflict warnings silently missing. Any future attempt must either key on
  the options too, or make capital-chart pass `{ sources }` first — which is a
  five-call-site prop change, since `CapitalChartProps` does not currently carry it.
- *The win is small*: sharing the five component calls saves about four walks.
  Meanwhile `src/lib/price-history.ts:118` calls `buildPositions` once per month
  and `:242` once per year, over growing `slice`/`filter` prefixes — 100+ walks
  that an identity-keyed memo **cannot** help, because each input is a fresh
  array. The component walks are not where the time goes.
- *No precedent exists*: zero derived Zustand selectors, no middleware, no
  `useShallow`, no `src/hooks/` directory, no memo helper in `src/lib/`. The
  repo's comments treat component-level `useMemo` as the deliberate seam
  (`live-prices-card.tsx:29-30`, `capital-chart.tsx:116-117`).

**A Content-Security-Policy.** Audited as S effort; it is not.

- `next-themes` (via `src/components/theme-provider.tsx:9`) injects a **blocking
  inline script** before paint — needs `'unsafe-inline'` or a nonce.
- `src/components/ui/chart.tsx:94-96` injects a `<style>` element via
  `dangerouslySetInnerHTML`, and Recharts adds many more inline styles at
  runtime — so `style-src` needs `'unsafe-inline'` or a nonce-everything approach.
- The PDF path is the one that genuinely needs `data:`/`blob:`:
  `html2canvas-pro` serialises the DOM through `data:`/`blob:` image and
  `foreignObject` loads, and `jsPDF`'s `save()` creates a `blob:` URL. A
  too-strict policy would fail the export into
  `pdf-export-button.tsx`'s generic toast, with the real reason only in the
  console.
- `next.config.ts` has **no `headers()` at all** and there is no
  `src/middleware.ts`, so a nonce-based policy means introducing middleware from
  scratch.
- *What is still cheap and worth doing eventually*: `connect-src 'self'` alone.
  The app makes exactly one `fetch` (`src/lib/live-prices.ts:206`, same-origin),
  fonts are self-hosted by `next/font/google` at build time, and the one external
  URL (`google-sheet.ts:206`) is a link target rather than a fetch. That single
  directive would encode the product's privacy promise in something the browser
  enforces, and nothing in the app conflicts with it.
